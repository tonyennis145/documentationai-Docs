## What will appear here

Future changelog entries can cover things such as:

- new product features
- meaningful changes to existing behavior
- new supported surfaces or major Connection capabilities
- important changes to permissions or administration
- deprecated or removed functionality
- other user-facing changes worth knowing about

Small documentation edits, internal experiments, and work that has not shipped should stay out of the changelog.

## How entries should be written

Each entry should explain:

1. **what changed**
2. **who it affects**
3. **what someone should do differently, if anything**
4. **where to learn more**

The changelog should reflect shipped product behavior rather than plans or assumptions.
