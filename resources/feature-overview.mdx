Giga brings company context, reusable AI work, and connected systems into one permission-aware product model.

The core idea is simple: keep the company’s durable context and access rules in Giga, then use that context from the interface and AI model that fits the work.

## Company Brain

**Company Brain** is Giga’s permission-aware company context layer.

It can combine relevant information from:

- workspace and Group guidance
- Tracks
- System Instructions
- memory
- files
- Integrations and live external data
- Agents
- Skills
- Workflows
- user-level context

Giga retrieves context according to the current user, permissions, and task.

## Chats

A [Chat](/chats/index) is the direct working surface between a user and Giga.

Use a Chat to ask questions, reason through work, create or edit supported work product, use Integrations, and take supported actions.

A Chat can link to at most **1 explicitly selected Track**.

Track selection is never inferred silently, because memory saved from the Chat becomes available to everyone on that Track.

## Groups

[Groups](/groups/index) are Giga’s main placement and permission scopes.

Groups can contain or scope resources such as:

- Tracks
- Agents
- files
- credentials and Integrations
- shared context

A user can access the Groups they belong to. For private work, set a Track to **Only me** instead of using a Group.

Use a Group when there is a real team boundary, shared area, or top-level access scope. Groups are managed in **Cloud → Organize → Groups**.

## Tracks

A [Track](/tracks/index) is Giga’s core primitive for work that continues over time.

Use a Track when context, decisions, files, and progress should accumulate around one effort.

A Track’s durable context is split across several layers:

| Layer | Purpose |
| --- | --- |
| Track brief | Stable background and standing instructions, in the Track's **Settings** tab |
| [Memory](/tracks/memory) | Current decisions, commitments, ideas, open questions, preferences, facts and procedures |
| [Files](/tracks/files) | Authored work product |
| Linked Chats | Working history around the Track |

Each Track has a Kind (Project, Area or Exploration). Track visibility follows the Group it lives in, or is set to **Only me**.

## System Instructions

[System Instructions](/library/context-cards) are standing background Giga reads before it works, kept in **Cloud → Shared Resources**. Each one can be shared with just you, a Group, a Track or the whole workspace.

Use them for things such as:

- what your company or team does
- stable constraints
- durable terminology
- standing instructions
- handoff context that should continue to matter

Background that belongs to a single Track goes in its **Track brief**. Fast-changing progress and decisions belong in Memory instead.

## Memory

[Giga Memory](/memory/index) remembers your company's work: one clear statement per memory, sorted into seven types (decision, commitment, idea, request, preference, fact, procedure), each with who said it and the evidence behind it.

- **It gets in** when someone says "save this" in ChatGPT, Claude or Slack, from chats in the Giga web app, or by pasting notes or importing a meeting link in **Brain**.
- **It stays current**: a new decision replaces the old one, a commitment closes when it's done, and repeats add evidence instead of duplicates.
- **It follows access**: memory filed to a Track is visible to that Track's people, and anything unfiled stays private in **Brain → To file** until you file it.

Memory stays separate from authored files.

## Files and databases

Files are authored work product.

Confirmed file capabilities include Markdown, text and binary Track files, code, webpages, and visual artifacts where the current surface supports them.

For structured growing records, Giga can use SQLite or a hosted Giga database when available.

Specific rich file-format claims should follow the current live capability rather than a fixed universal format list.

## Integrations

An [Integration](/connect/index) gives Giga permissioned access to an external system.

Integrations can represent:

- apps
- APIs
- databases
- MCP servers
- Cloud Browser Sessions
- messaging systems
- other supported services

An Integration can provide current information and, where the provider and Giga permissions allow it, support actions.

For custom Integrations, Giga currently prefers the strongest supported self-serve route in this order:

1. MCP
2. OAuth with supported self-serve registration
3. API key or PAT
4. browser login

Credentials are kept encrypted in [Cloud → Integrations](/connect/vault), not in Chats, files, or System Instructions. Every use of a credential is recorded and visible in **Settings → Activity & usage → Credential activity**.

## Agents

An [Agent](/agents/index) is a named reusable AI role.

An Agent can have:

- a role
- instructions
- durable context
- access to permitted Integrations
- Skills

Use an Agent when a reusable operating identity should work across multiple tasks or people.

Its actual access stays governed by the live Group and permission model.

## Skills

A [Skill](/skills/index) is reusable instructions and supporting context for a specific kind of task.

Use a Skill when the reusable asset is primarily **how to do something**.

Examples include a research method, review standard, handoff format, or task-specific operating procedure.

Skills can be owner-only or explicitly shared into Groups.

## Workflows

A [Workflow](/workflows/index) is a reusable multi-step process.

The current Workflow model supports:

- a name
- an optional description
- ordered meaningful steps
- plain-language instructions
- optional runtime inputs

Current input types can include text, Link, number, choice, and Yes / no where exposed by the live Workflow surface.

Keep Workflow steps focused on meaningful stages rather than individual tool calls.

## Pulses

A [Pulse](/pulses/index) is recurring scheduled work.

Use a Pulse when Giga should run a check or task automatically on a schedule.

Current Pulse scheduling supports:

- shared named schedule slots
- custom schedules
- daily cadence
- weekly cadence
- monthly cadence
- intra-day cadence

A Pulse can target an Agent, target a Track, or run without a target. Each Pulse has an On/Paused toggle.

Creating recurring work should be confirmed before it is scheduled.

## Permissions

Permissions run through the entire product.

Important layers include:

- workspace membership
- workspace role
- Group membership
- resource ownership
- Integration sharing
- external provider permissions
- current live tool permissions

A resource existing in the workspace does not automatically make it available to every user or Agent.

## Model flexibility

Giga's workspace context, permissions, Tracks, Skills, Workflows, and Integrations are separate from any single model provider.

Every workspace can use the **Giga managed** models out of the box. Admins can also bring their own model provider keys in **Settings → Model Providers**.

## Choosing the right feature

A quick rule of thumb:

| You need... | Use... |
| --- | --- |
| Direct ad hoc work | [Chat](/chats/index) |
| A team or access boundary | [Group](/groups/index) |
| Ongoing work with history | [Track](/tracks/index) |
| Standing background | [System Instructions](/library/context-cards) |
| A named reusable AI role | [Agent](/agents/index) |
| A reusable task method | [Skill](/skills/index) |
| A reusable ordered process | [Workflow](/workflows/index) |
| Recurring scheduled work | [Pulse](/pulses/index) |
| Live external-system access | [Integration](/connect/index) |
| Something to remember | [Memory](/memory/index) |
| Growing structured records | Database |
| Auth or secrets | Secure Integration flow |
