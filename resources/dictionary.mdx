Use this page as a quick reference for Giga’s product language.

The definitions below follow the current Giga product model. Exact workspace state, permissions, provider capabilities, and model availability still come from the live environment.

## Agent

An **Agent** is a named reusable AI role in Giga.

An Agent can have a role, instructions, context, access to permitted [Integrations](/connect/index), and [Skills](/skills/index).

Use an Agent when a reusable operating identity should be available across multiple tasks, people, or repeated interactions.

[Learn about Agents →](/agents/index)

## Brain

**Brain** is where your memory lives in the Giga web app. It shows current memory by type, the **To file** inbox, the Evidence log and Brainstorms, and lets you add memory by pasting notes or importing a link.

[Learn about Giga Memory →](/memory/index)

## Chat

A **Chat** is the direct working surface between a user and Giga.

Use a Chat to ask questions, reason through work, create or edit supported work product, use Integrations, and ask Giga to take supported actions.

A Chat can be linked to at most **1 explicitly selected Track**.

[Learn about Chats →](/chats/index)

## Chat history

**Chat history** is the transcript of the interaction inside a Chat.

It is separate from durable Track context such as System Instructions, memory, and files.

[Learn about Chat history →](/chats/history)

## Company Brain

**Company Brain** is Giga’s permission-aware company context layer.

Depending on relevance and access, it can draw from workspace and Group guidance, Tracks, System Instructions, memory, files, Integrations, Agents, Skills, Workflows, and user-level context.

Company Brain is structured around permissions and the work it belongs to.

[See the Feature Overview →](/resources/feature-overview)

## Integration

An **Integration** gives Giga permissioned access to an external system.

Integrations can represent apps, APIs, databases, MCP servers, Cloud Browser Sessions, messaging systems, and other supported services. You manage them in **Cloud → Integrations**.

An Integration can provide live information and support actions when the current Giga and provider permissions allow it.

[Learn about Giga Connect →](/connect/index)

## Credential

A **credential** is secure authentication material behind some Integrations.

Examples can include authentication tokens, API credentials, connection strings, or login material depending on the Integration method.

Credentials are kept in [Cloud → Integrations](/connect/vault) and should stay in the secure connection flow rather than ordinary Chats, System Instructions, or files.

[Learn about Cloud →](/connect/vault)

## Database

A **database** is a structured store for records that are repetitive, tabular, updated field by field, filtered, sorted, aggregated, or expected to grow.

Current Giga doctrine supports SQLite and hosted Giga databases where the relevant capability is available.

Use files for authored narrative work such as reports and drafts.

[Learn about Files in Tracks →](/tracks/files)

## File

A **file** is authored work product.

Files can hold reports, drafts, notes, code, webpages, exports, and other supported artifacts.

Files are separate from Track memory. A Track can have rich context and history even when its file area is empty.

[Learn about Files in Tracks →](/tracks/files)

## Group

A **Group** is a placement and permission scope in Giga.

Groups can contain or scope resources such as Tracks, Agents, files, credentials, Integrations, and shared context.

Use a Group when there is a real team boundary, shared area, or top-level access scope. Groups are managed in **Cloud → Organize → Groups**.

[Learn about Groups →](/groups/index)

## Evidence

**Evidence** is the append-only record behind each memory: what was said, a quote, who said it, when, and where it came from. Evidence is never rewritten. You can read all of it in **Brain → Evidence log**.

[Learn about Giga Memory →](/memory/index)

## Memory

**Memory** is what Giga knows about your company's work: one clear statement per memory, each with a type (decision, commitment, idea, request, preference, fact or procedure), who said it, and the evidence behind it.

Memory belongs to a Track and is visible to the people on that Track, or stays private to the person who saved it until they file it. It stays current: a new decision replaces the old one, and a commitment closes when someone says it's done.

[Learn about Giga Memory →](/memory/index)

## Model provider

A **model provider** is a source of AI models Giga can use. Every workspace has the **Giga managed** provider; admins can add their own keys for other providers in **Settings → Model Providers**.

[Learn about Giga Connect →](/connect/index)

## Only me

**Only me** is the setting for a private Track. There is no private Group: a Track set to **Only me** belongs to no Group and is visible only to you.

A separate Group is unnecessary simply to make a Track private.

[Learn about Personal vs shared work →](/groups/personal-vs-shared)

## Pulse

A **Pulse** is recurring scheduled work.

Use a Pulse when Giga should run a check or task on a schedule instead of waiting for someone to ask in a Chat.

A Pulse can target an Agent, target a Track, or run without a target.

[Learn about Pulses →](/pulses/index)

## Shared Group

A **shared Group** is a Group used for team work.

Membership in the shared Group helps determine which people can access the resources inside its permission scope.

[Learn about Groups →](/groups/index)

## Skill

A **Skill** is reusable instructions and supporting context for a specific kind of task.

Use a Skill when the reusable asset is primarily the method, rules, standard, template, or reference context for doing the task.

[Learn about Skills →](/skills/index)

## System Instructions

**System Instructions** are standing background Giga reads before it works, such as who you are, what your company does, or how a kind of work should be done. They were previously called Context Cards and Context Notes. Each one can be shared with just you, a Group, a Track or the whole workspace. Find them in **Cloud → Shared Resources → System Instructions**.

A Track's own standing background lives in its **Track brief**, in the Track's **Settings** tab. Fast-changing progress and decisions belong in Track memory.

[Learn about System Instructions →](/library/context-cards)

## Surface

A **surface** is a user-facing interface where someone can work with Giga.

Current official Giga surfaces are:

- Giga Web
- Slack
- ChatGPT
- Claude
- Microsoft Teams

The underlying Giga context and permissions stay consistent, while exact UI, file behavior, and available capabilities can differ by surface.

[Learn about using Giga anywhere →](/use-giga-anywhere/index)

## Track

A **Track** is Giga’s core long-running work primitive.

Use a Track when context, decisions, files, and progress should accumulate around an effort over time.

A Track has a Kind (Project, Area or Exploration) and can contain durable context across its Track brief, System Instructions, memory, linked Chats, and files.

Track visibility follows the Group it lives in, or is set to **Only me**.

[Learn about Tracks →](/tracks/index)

## To file

**To file** is the inbox in Brain for memory saved without a Track. Items there are private to you, each with Giga's suggested Track. File them to a Track to share them with that Track's people, or keep them private.

[Learn about Giga Memory →](/memory/index#where-memory-goes-tracks-or-private-until-you-file-it)

## Cloud

**Cloud** (formerly Vault) is where the credentials behind your Integrations are kept, in **Cloud → Integrations**: Direct (OAuth & MCP), API Keys, Logins, Databases and Cloud Browser Sessions. Secrets are encrypted and never shown to the AI or sent back to your browser.

[Learn about Cloud →](/connect/vault)

## Workflow

A **Workflow** is a reusable multi-step process.

Use a Workflow when several meaningful ordered stages should be saved, standardized, or run again later.

Current Workflows can have a name, description, ordered steps, plain-language instructions, and optional runtime inputs.

[Learn about Workflows →](/workflows/index)

## Workspace

A **workspace** is the top-level Giga environment for a company or team.

Workspace membership, Groups, context, Integrations, and other resources all sit within that environment.

The current workspace state is the source of truth for what a user can access.

[Learn about Teams & Admin →](/teams-and-admin/index)
