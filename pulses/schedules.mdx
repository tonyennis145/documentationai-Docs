A Pulse schedule controls **when recurring work runs**.

You set it under **When it runs** in the Pulse's Settings. The current Pulse model supports 2 scheduling approaches: **Saved times** and **its own schedule**.

## Saved times

Saved times are reusable named times already available in the workspace, like “Morning”.

A Pulse can attach to one or more Saved times.

  <Card title="Shared timing" href="/pulses/schedules" icon="calendar">

  </Card>
  <Card title="Current workspace" href="/pulses/managing" icon="clock">

</Columns>

Giga should read the current Pulse configuration to see which Saved times are available rather than assuming a fixed list.

## Its own schedule

Choosing **Its own schedule** gives the Pulse its own recurring cadence.

The current Pulse model supports:

- daily
- weekly
- monthly
- intra-day

Choose the cadence that matches how often the recurring job should run.

> **Use the live schedule options**
>
> Exact schedule details and available Saved times can change. Giga should use the current Pulse configuration as the source of truth.

## Saved times vs its own schedule

| Schedule type | Good fit |
| --- | --- |
| **Saved times** | The Pulse should run at an existing workspace time |
| **Its own schedule** | The Pulse needs its own daily, weekly, monthly, or intra-day cadence |

The work itself still comes from the Pulse Prompt and the optional [Agent](/agents/index) or [Track](/tracks/index) it is connected to.

## Schedule and connection are separate

The schedule answers **when the Pulse runs**.

**Connected to** answers **what context or role the Pulse runs as**.

For example:

  <Card title="Schedule" href="/pulses/schedules" icon="clock">

  </Card>
  <Card title="Connected to" href="/pulses/with-agents" icon="bot">

A Pulse can also be connected to a Track, or not connected at all.

## Editing a schedule

Changing a Pulse schedule changes future recurring behavior.

Giga should read the current Pulse before editing it because the current update operation replaces the full Pulse definition.

That means an update should preserve every setting that should remain, including:

- name
- Prompt
- schedule type
- cadence or selected Saved times
- Connected to

> **Read before updating**
>
> Omitting an existing Pulse setting from the replacement definition can reset it.

[Learn about Managing Pulses →](/pulses/managing)

## Choosing the cadence

Match the schedule to how quickly the underlying work changes.

For example:

- **daily** can fit information that changes every day
- **weekly** can fit recurring team reviews
- **monthly** can fit slower reporting cycles
- **intra-day** can fit work that needs several checks within a day

The right cadence depends on the job. Avoid scheduling work more frequently than it needs to run.

## A simple example

Imagine a **Weekly Pipeline Review** Pulse.

| Setting | Example |
| --- | --- |
| **Prompt** | Review meaningful pipeline changes and summarize what needs attention |
| **Schedule type** | Its own schedule |
| **Cadence** | Weekly |
| **Connected to** | Sales Reporting Agent |

Another Pulse could use a Saved time instead while keeping the same Prompt.
