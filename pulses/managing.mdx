A Pulse keeps running on its saved schedule until you pause it, change it, or remove it.

Managing a Pulse usually means reviewing its current setup, changing part of the recurring job, pausing it, or deleting it when the scheduled work is no longer needed. Open a Pulse from **Cloud → Build & Automate → Pulses** to see its **Runs** and **Settings** tabs.

## Review the current Pulse first

Before changing a Pulse, Giga should read the current Pulse definition.

That lets you review:

- name
- Prompt
- schedule type
- cadence or selected Saved times
- what it's Connected to: an Agent, a Track, or nothing

The live Pulse list is also the source of truth for the Saved times currently available in the workspace.

> **Read before updating**
>
> The current Pulse update operation replaces the full desired definition. Giga should preserve every existing setting that should remain.

## Updating a Pulse safely

<Steps>
  <Step title="Read the current definition" icon="search">
    Review every saved setting before making a change.
  </Step>
  <Step title="Change the intended field" icon="edit-3">
    Update the Prompt, schedule, connection, or name that needs to change.
  </Step>
  <Step title="Preserve everything else" icon="list-checks">
    Keep the existing settings that should remain part of the Pulse.
  </Step>
  <Step title="Save the full definition" icon="save">
    Submit the complete desired Pulse configuration.
  </Step>
</Steps>

For example, changing a Pulse from weekly to daily should not accidentally remove its connection or Prompt.

## Changing the schedule

A Pulse can use **Saved times** or **its own schedule**.

If you change between those scheduling models, review the full schedule setup so the new definition is complete.

The current custom cadences are:

- daily
- weekly
- monthly
- intra-day

[Learn about Pulse schedules →](/pulses/schedules)

## Changing what it's connected to

A Pulse can currently be connected to:

- an [Agent](/agents/index)
- a [Track](/tracks/index)
- nothing (it still runs, but writes no updates)

Changing the connection can materially change the context available to future scheduled runs.

Before switching, check that the new Agent or Track is the intended home for the recurring work and that the required permissions and Integrations are available.

## Changes to Agents and Tracks can affect future runs

You do not always need to edit the Pulse when the surrounding context changes.

A Pulse connected to an Agent uses the current Agent configuration at run time.

A Pulse connected to a Track uses the current Track context available at run time.

That means future runs can reflect changes to:

- Agent instructions
- Agent context
- Skills
- Integrations
- Track context
- provider permissions
- external data

Edit the Pulse itself when the Prompt, schedule, or connection needs to change.

## When a Pulse stops producing useful results

If a recurring result becomes less useful, check the right layer before rewriting everything.

| Problem | Check first |
| --- | --- |
| The job itself is wrong | Pulse Prompt |
| It runs too often or too rarely | Pulse schedule |
| It uses the wrong role | Connected Agent |
| It belongs to different ongoing work | Connected Track |
| Required data is missing | Integrations and provider permissions |
| The task method needs improvement | Relevant Skill or Agent instructions |

This helps keep scheduling, context, access, and task methods in their proper places.

## Pausing a Pulse

Each Pulse has an **On / Paused** toggle at the top of its page. Switch it to **Paused** to stop scheduled runs without losing any settings, and switch it back **On** to resume. You can still start a paused Pulse by hand with **Run now**.

## Removing a Pulse

Deleting a Pulse stops it running and removes it with its run history.

Giga should confirm before deletion because future runs will stop.

> **Delete only when the recurring job should end**
>
> If the job still matters but needs different timing, a different Prompt, or different context, update the Pulse instead. If it just needs a break, pause it.

## A simple example

Imagine a **Weekly Customer Health Review** Pulse currently connected to a Customer Success Agent.

The team decides it should run monthly and focus only on material risks.

A safe update would:

1. read the current Pulse
2. preserve its name and connected Agent
3. change the Prompt to focus on material risks
4. change the custom cadence from weekly to monthly
5. save the complete revised definition
