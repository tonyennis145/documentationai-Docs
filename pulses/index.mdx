A **Pulse** is recurring scheduled work in Giga.

Use a Pulse when Giga should perform a check or piece of work automatically on a schedule instead of waiting for someone to ask in a [Chat](/chats/index).

You'll find Pulses under **Cloud → Build & Automate → Pulses**.

## What a Pulse contains

A Pulse can include:

- a name
- a **Prompt**: what the agent does each time the Pulse runs
- a schedule (**When it runs**)
- an optional **Connected to** setting

**Connected to** is the [Agent](/agents/index) or [Track](/tracks/index) the Pulse runs as and writes updates to. Without one, the Pulse still runs, but writes no updates.

The exact schedule options and available Agents and Tracks come from the live workspace.

## Pulse vs Chat vs Workflow

| Primitive | Best fit |
| --- | --- |
| **Chat** | Work that starts when a person asks |
| **Workflow** | A reusable ordered process |
| **Pulse** | Work that should happen automatically on a recurring schedule |
| **Agent** | A reusable AI role that a Pulse can run through |
| **Track** | An ongoing body of work that a Pulse can run against |

A Pulse answers **when should this work run?**

A [Workflow](/workflows/index) answers **what ordered process should be reused?**

## Scheduling options

The current Pulse model supports:

- **Saved times**: reusable named times, like “Morning”
- **Its own schedule**: a custom cadence
- daily cadence
- weekly cadence
- monthly cadence
- intra-day cadence

Saved times let a Pulse use one of the workspace’s existing named times.

Its own schedule gives the Pulse a custom cadence.

[Learn about Pulse schedules →](/pulses/schedules)

## What can a Pulse do?

The Prompt can ask Giga to perform work using the context and capabilities available when the Pulse runs.

Examples include:

- check a Track for meaningful changes
- prepare a recurring account update
- run a periodic research check
- review a set of current signals
- produce a scheduled summary through an Agent

Access still depends on the live environment. A Pulse does not create new permissions or Integrations.

## Pulses and Agents

A Pulse can be connected to an Agent.

This is useful when recurring work should run with a consistent role, instructions, context, Skills, and Integrations.

For example, a Reporting Agent could run a weekly review through a Pulse when those resources are available in the current workspace.

[Learn about Pulses with Agents →](/pulses/with-agents)

## Pulses and Tracks

A Pulse can also be connected to a Track.

This is useful when the scheduled task belongs to one ongoing body of work, such as:

- a customer account
- a launch
- a hiring effort
- an ongoing research area

The Pulse can then run with the Track context available at that time.

> **Track access still matters**
>
> Connecting a Pulse to a Track does not widen its audience. The Track continues to follow its Group and permission boundaries.

## Live data stays live

A Pulse runs in the environment that exists at execution time.

That means the available:

- Integrations
- provider permissions
- Track memory
- Agent context
- Skills
- external data

can change between runs.

The Pulse defines the Prompt and schedule. Giga still checks the live environment when the work runs.

## Creating recurring behavior deserves confirmation

A Pulse causes future work to run automatically.

Giga should confirm the user’s intent before creating one, especially the Prompt, schedule, and what it is connected to.

Deleting a Pulse should also be confirmed.
