title: API keys
description: Keys and tokens for services that don't use OAuth. Giga attaches them to requests for you, so they never appear in a chat.
---

**Add a key once. Agents use it by name. Nobody, not even the AI, sees it again.**

<Tabs>
  <Tab title="1 · How it works" icon="key-round">
    <Image src="https://blob-cdn.documentation.ai/org-d896f59c-62b4-41f0-9b51-36d7bf1ed9d0/doc-ed7f1cc1-783d-498c-8dca-196c97bbef03/1792478921501-hi9g06d4jjq-vault-api-key-flow.svg?rasterize-bypass=true" alt="You paste the key once; the Vault keeps it encrypted; Giga's proxy adds it to the request; the service sees a normal request" />

    Agents refer to a key by its **handle**, like `airtable`. Giga's proxy attaches the key to the request, so the agent only ever sees the answer.
  </Tab>
  <Tab title="2 · Add one" icon="plus">
    Ask in any chat:

    > **You:** Hey Giga, I need to add an API key for Airtable.
    >
    > **Giga:** Here's a secure link. I've filled in the name and handle, so just paste the key.

    Or click **+** at the top of **Vault → API Keys**.
  </Tab>
  <Tab title="3 · Use it" icon="sparkles">
    Just ask for the work. Giga picks the right key.

    > **You:** List the tables in our Airtable Hiring base.

    > **You:** Any new Sentry errors since yesterday?

    > **You:** Which API keys can I use?
  </Tab>
  <Tab title="4 · Share it" icon="users">
    Keys are **private until you share them.** Open a key to share it with a Group or a person, or link it to a Track.

    People you share with can **use** it, but can't see, change or delete it.
  </Tab>
</Tabs>

<Callout kind="tip">Does the service have a "Sign in with…" option? Use [Integrations](/connect/connecting) instead. OAuth connections refresh themselves.</Callout>

<ExpandableGroup>
  <Expandable title="Why not just paste the key into chat?">
    Giga can save a key you paste, but it then sits in that chat's history. The secure link keeps it out of the conversation entirely.
  </Expandable>
  <Expandable title="Can I see the key again after saving it?">
    No. Keys are never sent back to the browser. If you've lost it, create a new key with the service and add that.
  </Expandable>
  <Expandable title="How do I replace an expired key?">
    Remove the old key and add the new one with the same handle. Agents using the handle pick it up straight away.
  </Expandable>
  <Expandable title="Where does Giga put the key in the request?">
    Usually as a bearer token in the `Authorization` header. Some services want a different header (like `X-API-Key`), a URL parameter or Basic auth. Giga picks the right one when it saves the key.
  </Expandable>
  <Expandable title="Can a key be pointed at any address?">
    Only public ones. Giga refuses requests to internal, loopback or cloud-metadata addresses.
  </Expandable>
</ExpandableGroup>
