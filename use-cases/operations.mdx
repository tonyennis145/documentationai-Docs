Operations work is full of recurring processes, handoffs, exceptions, and information spread across different systems.

Giga can help keep that work organized around the right Tracks, reusable methods, Workflows, recurring Pulses, and live Connections.

## Organize ongoing operational work with Tracks

Use a [Track](/tracks/index) when an operational area or initiative needs continuity.

Examples include:

- vendor onboarding
- a customer implementation
- an internal rollout
- recurring compliance preparation
- a process-improvement effort
- an operational issue that will evolve over time

The Track keeps durable background, memory, Current Track State, files, and linked Chats around that work.

## Standardize repeatable tasks with Skills

A [Skill](/skills/index) can capture the method for a task your operations team repeats.

Examples include:

- reviewing an intake request
- preparing a handoff
- checking a record against an internal standard
- summarizing an operational issue
- preparing a recurring status update

The Skill keeps the task method reusable without tying it to one specific project or person.

## Turn multi-step processes into Workflows

A [Workflow](/workflows/index) fits an operational process with several meaningful stages.

For example, a **Vendor Intake Review** Workflow might include:

<Steps>
  <Step title="Gather the request" icon="file-text" title-type="p">
    Collect the information required to understand the vendor and the requested use.
  </Step>

  <Step title="Review against the standard" icon="check-square" title-type="p">
    Apply the relevant internal method, requirements, and available evidence.
  </Step>

  <Step title="Identify missing information" icon="search" title-type="p">
    Surface gaps, unresolved questions, or blockers.
  </Step>

  <Step title="Prepare the handoff" icon="users" title-type="p">
    Return a concise summary for the person responsible for the next stage.
  </Step>
</Steps>

The Workflow stores the ordered process. Skills can provide reusable methods inside individual steps.

## Work across connected systems

[Connections](/connections/index) let operations teams work with live systems when the current workspace and provider permissions allow it.

Depending on what is connected, Giga can retrieve current information or perform supported actions through:

- APIs
- databases
- MCP servers
- browser-based systems
- other approved integrations

Giga should use the live Connection surface rather than assume a particular system or action is available.

## Keep structured operational records structured

Operational data can grow quickly.

When the work involves repetitive, tabular records that need filtering, sorting, aggregation, or field-by-field updates, a database can be a better fit than a long narrative file.

When the work is a human-readable report, plan, summary, or draft, use a file.

> **Choose the storage model based on the work**
>
> Track memory preserves context and decisions. Files hold authored work product. Databases fit growing structured records.

## Schedule recurring checks with Pulses

A [Pulse](/pulses/index) can run recurring operational work.

Examples include:

- a daily exception review
- a weekly implementation check-in
- a monthly vendor review
- a recurring operational summary
- a scheduled check against an ongoing Track

The Pulse can target an Agent, a Track, or run without a target, depending on where the recurring context belongs.

## Use an Operations Agent for a stable role

An [Agent](/agents/index) can be useful when the team wants a consistent operational role across repeated work.

For example, an Operations Agent might:

- follow the team’s standing operating instructions
- use approved operational Connections
- apply shared Skills
- prepare recurring summaries
- support several operational tasks within the same Group scope

The live Agent configuration determines its actual access.

## Handle exceptions explicitly

Operational work often breaks because something is missing, blocked, or outside the normal path.

Workflow steps and Pulse instructions can tell Giga what to do when that happens.

For example:

> If a required field or approval is missing, stop the process and return exactly what is needed before the work can continue.

This is more reliable than silently filling gaps or pretending the process completed.

## Keep handoffs grounded

When work moves between people, store the durable information in the right place.

For an operational Track:

- Context Notes hold stable background and standing instructions
- Observations preserve meaningful developments
- Current Track State keeps the current position and decision record
- Files hold authored reports, drafts, and deliverables

A handoff Skill or Workflow can then turn that context into a concise package for the next person.
