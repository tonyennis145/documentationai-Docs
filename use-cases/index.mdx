Giga’s building blocks can be combined around the way different teams actually work.

The examples in this section are **patterns**, not fixed templates. The exact systems, data, and actions available depend on the [Connections](/connections/index), permissions, and live capabilities in your workspace.

## Start with the work

A useful Giga setup usually begins with the job that needs to get done.

Then choose the primitives that fit it:

| Need                                  | Giga primitive                        |
| ------------------------------------- | ------------------------------------- |
| Work through something directly       | [Chat](/chats/index)                  |
| Keep an ongoing body of work together | [Track](/tracks/index)                |
| Give Giga durable standing background | [Context Note](/tracks/context-notes) |
| Reuse a named AI role                 | [Agent](/agents/index)                |
| Reuse a task method                   | [Skill](/skills/index)                |
| Reuse an ordered process              | [Workflow](/workflows/index)          |
| Run recurring work on a schedule      | [Pulse](/pulses/index)                |
| Work with live external systems       | [Connection](/connections/index)      |

Most useful setups combine several of these rather than relying on one feature alone.

## Example: one use case, several building blocks

Imagine a Sales team preparing for an account review.

<Steps>
  <Step title="Keep the account work in a Track" icon="folder" title-type="p">
    Store the ongoing account context, decisions, memory, and work product together.
  </Step>

  <Step title="Use live Connections" icon="plug" title-type="p">
    Pull current information from approved sales systems when the workspace makes those Connections available.
  </Step>

  <Step title="Apply a Skill" icon="sparkles" title-type="p">
    Reuse the team’s standard account-research or review method.
  </Step>

  <Step title="Run through an Agent" icon="bot" title-type="p">
    Use a named Sales Agent when a consistent role and operating context are helpful.
  </Step>

  <Step title="Schedule recurring work with a Pulse" icon="clock" title-type="p">
    Add recurring review only when the work genuinely needs to happen on a schedule.
  </Step>
</Steps>

Each primitive has a specific job. Together, they can form a reusable way of working.

## Company Brain sits underneath the use case

Across these examples, Giga’s **Company Brain** remains permission-aware.

The context available to the work can include relevant:

- workspace and Group guidance
- Tracks, Context Notes, Observations, and Current Track State
- files
- Agents and Skills
- Workflows
- Connections and live external information
- user-level context

Giga retrieves what is relevant and permitted for the current task.

## Use cases follow permissions

A use case does not bypass Giga’s access model.

For example:

- a Sales Agent cannot use a CRM Connection that is unavailable in its scope
- a teammate cannot access a Track simply because another teammate can
- a Workflow cannot invent access to a system
- a Pulse cannot create permissions by scheduling the work
- a Chat should not silently attach itself to a Track

The live workspace remains the source of truth.

## Use cases are adaptable

These examples are meant to show how the primitives fit around real work.

They are not claims that every company uses the same process or that every named external system is automatically supported.

When a use case depends on an external tool, Giga should check the current integration and Connection surface before promising the exact action.
